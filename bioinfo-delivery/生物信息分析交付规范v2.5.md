## 现有流程优先

所有生信分析与绘图优先复用既有项目流程、个人环境的 ytbiokit 及其扩展；已有流程可完成时，不另写分析函数。需修饰、调整、后处理或补充分析实现时，动手前先告知用户现有入口、原因、拟改内容及影响。完整执行规则见[现有流程优先](/home/taojj/bioinfo-plotting/SKILL.md#现有流程优先所有生信分析适用)。

## 10 条规范

- 新项目统一使用 prj\_init 初始化，自动生成 analysis\.ipynb、Data、Results、Scripts。

- Data/Raw 保存原始数据；清洗数据、分析过程、检查点和缓存统一放 Data/Processed。

- Processed 与 Scripts 的分析步骤按 `NN.short_name` 一一对应；Results 仅保留通过模块准入闸门的结果叶子，并按独立编号的大类组织，不要求与单个内部步骤同名同号。内部步骤到 Results 大类及结果叶子的来源映射记录在对应 Processed `run_summary.yaml`，Results 内使用相对路径导航。

- analysis\.ipynb 是交互式草稿本；可调用 Python/R/Bash，但可复用逻辑必须进入 Scripts。

- 工具、参数、参考数据和随机 seed 必须可追溯，且不在代码中隐式写死。

- 缓存只用于高成本步骤；命中前验证，写入必须原子化，损坏时明确报错。

- 表格默认 UTF\-8 TSV；全量/筛选结果分别使用 \*\.full\.tsv 与 \*\.filtered\.tsv。

- 所有正式分析图必须由 Scripts 中可复现的 R/Python 等代码直接从结果证据链中的当前定稿分析数据集生成，并由脚本导出 PDF/PNG；不得使用生成式图片或 AI 图像工具、手工拼图、截图或图像编辑软件合成正式分析图。适用的图形类型应尽量全面；论文型图形同时交付 PDF 和 300 dpi PNG，配色统一读取 Scripts/config/colors\.yaml；图形使用描述内容的语义文件名，可拆图分别交付，不使用 facet；基因表达图逐基因输出，所有包含组间比较的表达量图同时标注显著性星号与精确 P 值并保留 stat 表。

- 分析成功但无显著结果时可保留空表；图片不得生成或保留说明性占位图。

- Results 只包含至少有一对可解释结果图的客户结果叶子及项目说明；纯下载、校验、转换、provenance 或流程门控模块留在 Processed。

## 适用边界

**按产物类型适用：**纯转换、数据获取或 provenance 审计不强制画图，但不得因此创建无图的 Results 结果叶子；低成本步骤不强制缓存；正常生物学分析得到零条筛选结果时，允许保留只有稳定表头的 filtered 表，并交付能够解释该零结果的真实分析图。

|**位置**|**只放什么**|**禁止事项**|
|---|---|---|
|analysis\.ipynb|交互式草稿本：调用脚本、临时整理数据、探索和抽查|不得保存唯一分析逻辑，不作为正式交付结果的唯一来源|
|Data/Raw|下载/接收的原始数据、原始 manifest 与校验和|不得覆盖、清洗或手工改名后冒充原始数据|
|Data/Processed|清洗数据、编号分析目录、Input/Output、检查点、缓存和运行摘要|不得直接作为客户交付目录|
|Results|通过模块准入闸门的客户最终表格、图形、源数据和结果说明|不得放无有效结果图的纯获取/审计/转换模块，也不得放运行摘要、日志、状态码、命令、脚本、缓存或内部路径|
|Scripts|脚本、测试、公共函数及项目级 colors\.yaml 配色配置|不得复制真实客户数据、凭据或硬编码内部路径|

**目录参考｜**可参考套用整个 `/data/Projects/Examples/`：按实际项目类型选择 `scRNA-Results`、`Bulk-Results`、`网药-Results` 等对应示例，查看其 `Results/` 与 `Report/`（报告）目录的实际层级组织和命名，采用适合当前分析内容的结构。scRNA 的大类树状结构是示例之一；只创建实际有交付内容的模块，不机械复制示例中的无关或空模块；Results 的准入、叶子 `Tables/` 和 `Figures/` 以及 PDF/PNG 要求继续按本规范执行。

- 单细胞多样本合并 AnnData 时必须 `ad.concat(join="outer")` 保留基因并集，禁止默认 inner 交集丢基因；合并前先对每个样本 `var_names_make_unique()`，并给 cell barcode 加样本前缀防止重名。

- 肿瘤单细胞项目必须同时使用全局 `tumor-infercnv-purification` skill：实际运行 inferCNV，建立可逆的高置信恶性、正常样和不确定分类；下游肿瘤细胞分析默认只使用通过纯度门槛的高置信细胞。
- 每次聚类、谱系二次聚类及细胞类型/亚型注释完成或修订后，必须基于最新定稿对象及分组重新运行 FindMarkers；全簇可使用 FindAllMarkers。核验并更新 marker 全量/筛选表及注释对应关系，不能仅改旧表标签或沿用旧检测缓存。具体执行读取[聚类与注释后的 marker 重跑规则](/home/taojj/.agents/skills/bioinfo-plotting/references/post-annotation-markers.md)，通过后再完成该版注释及可视化。

- 连续数值配色规则：相关性、z-score 标准化值、logFC 等含正负且以零为中心的热图统一使用 `RdBu_r` 发散配色（红正蓝负、零为白）；网络图中的度值（degree）映射统一使用 `Spectral`；具有明确“小→大”顺序的非负或单调连续数值（如表达量）统一使用 `Reds` 或 `magma` 顺序色图，不使用发散色图。热图单元格尽量保持正方形（aspect equal）。

## 文件夹与各级子目录命名

文件夹与各级子目录命名：项目分析目录及交付目录均按分析内容、数据集、分组比较或分析对象命名，不使用软件包或绘图库名字（包括 ytbiokit），也不把包名作为目录名的一部分。例如 `21.ytbiokit_scrna` 应命名为 `21.expression_scores`，细胞通讯用 `CellCommunication`，调控网络用 `RegulatoryNetwork`。内部步骤沿用原编号，Scripts 与 Data/Processed 的对应目录同名同号；交付大类按自身编号管理。重命名既有目录时先检查重名冲突，再同步脚本配置、输入输出路径、运行记录、图形索引和 HTML/README 的全部引用，并验证链接与流程有效。此规则约束项目目录命名，不重命名软件安装目录、Python/R 包目录、skill 名称或真实基因/通路标识。

# 03  开发：可复现、可恢复、可报错

## 3\.1 生物信息可复现性

- 记录工具名称/版本、全部关键参数、参考数据库名称/版本/发布日期/校验和。

- 参考基因组、数据库和物种不得隐式写死；配置中必须声明默认值、允许值和实际值。

- 随机算法必须接受 seed；run\_summary\.yaml 记录实际 seed。

- 输入文件记录内容摘要；外部数据记录 accession、下载日期和来源。

- 正式分析图的输入必须是结果证据链中的当前定稿分析数据集：已按既定流程完成适用且可追溯的质控、过滤、标准化、批次校正或标签/注释修订；不得擅自回退到证据链中已被替代的旧版本绕过上游修订。方法要求使用原始计数时，使用定稿样本与特征集合所对应的原始计数层，并明确记录该口径。run\_summary\.yaml 与来源记录须追踪输入版本、处理步骤和摘要。对分析数据的处理仅限预先定义或有科学依据的处理，禁止为提高 AUC、显著性或迎合预期结论而改动数据、删样本或调标签。

**验收句｜****同一份输入 \+ 同一组参数 \+ 同一工具/参考版本，应得到等价结果。**

## 3\.2 缓存与断点续跑

**缓存键 = **输入内容摘要 \+ 全部结果相关参数 \+ 工具版本 \+ 参考数据版本

- 只为高成本步骤增加缓存；低成本转换直接重算。

- 命中缓存时验证元数据、schema、文件大小/行列数等结构，不得只判断文件存在。

- 缓存损坏或不兼容时停止并给出可操作错误，提示使用 \-\-force 或清理指定缓存。

- 先写临时文件，校验成功后原子 rename；失败/中断不得留下看似有效的半成品。

- 检查点写入 Data/Processed；Results 只接收通过校验的正式结果。

- 缓存、临时文件、运行结果不得提交 Git。

发现缓存 → 校验 key 与结构 → 有效则复用
                         ↘ 无效则明确报错并提示 \-\-force
无缓存/强制重跑 → 写 \*\.tmp → 校验 → 原子改名 → 记录完成状态

## 3\.3 错误处理与日志

- 失败即失败：返回非零状态，并说明步骤、对象、原因和建议动作。

- 运行失败不得用空表替代；算法正常完成但筛选结果为零时，可以保留有稳定表头的空结果表。

- 日志记录状态、计数、版本和参数摘要；不记录绝对路径、用户名、主机名、令牌或完整环境。

# 05  结果：表格和图形必须可解释

## 5\.0 模块准入闸门

Results 是分析结果叶子的交付集合，不是 Processed 的镜像。创建 `Results/N\.Category/` 或其结果叶子前，同时检查分析性质与图形证据。顶层大类用于独立导航，叶子目录用于实际承载交付内容：

- 准入：模块直接产生可解释的生物学结果图，或产生解释下游生物学结果所必需的 QC、整合、批次校正、标志物校对或验证图；至少有一个真实语义图形基础名同时具备 PDF 和 300 dpi PNG。
- 不准入：模块只做下载、文件获取、checksum、解压、格式转换、来源/provenance、样本字段审计、归档清单或流程 `go/no-go` 门控，且没有上述有效图形。该模块完整保留在 `Data/Processed/` 与 `Scripts/`，不创建客户 Results 模块。
- 零结果不等于零图：生物学分析正常完成但无显著条目时，保留全量/空 filtered 表，并交付能够呈现实际效应、分布、诊断或阴性结果的真实分析图；不得用说明性占位图满足准入条件。
- 禁止空壳：不为内部模块或无有效图形的结果分支创建空 `Figures/`、空 `Tables/figure_index.tsv`、仅写流程状态的 README 或占位图。Results 大类编号可因未设立对应交付大类而出现空缺；一个大类下的各结果叶子仍须分别通过准入。

完成标准：Results 中每个结果叶子都能说明其图形对生物学结论、质控可信度或验证边界的必要贡献，并至少有一对可打开的 PDF/PNG；不满足者留在对应 Processed 分析目录，不创建交付叶子。

## 5\.1 表格

- 每个结果叶子的全部 TSV（包括 figure\_index\.tsv 与统计表）只能放在该叶子的 `Tables/`；不得散落在大类、分支或叶子根目录。没有分支的大类自身就是叶子，可直接使用 `Results/N\.Category/Tables/`。

- 默认 UTF\-8 TSV，首行列名稳定；README 说明缺失值编码、数值精度和关键列含义。

- 同时交付全量和筛选结果时使用 \*\.full\.tsv 与 \*\.filtered\.tsv，并写明筛选规则。

- 保留稳定 ID；不要只交付基因符号而丢失 Ensembl/Entrez 等主键。

- 显著性、效应量、样本量和比较方向必须可核对；禁止只交显著条目而无全量统计。

- 按确定规则排序，列顺序固定；导出前检查重复列名、乱码、科学计数法，并区分合法空结果与导出失败。
## 5\.2 图形

|**项目**|**交付标准**|
|---|---|
|目录|全部 PDF/PNG/SVG 只放在结果叶子的 `Figures/`；每个图形基础名同时提供 PDF 与 PNG|
|格式|论文型图形在适用时同时生成矢量 PDF 与 300 dpi PNG|
|可读性|**一律不加 title 与 subtitle**；坐标轴/单位/图例完整；缩放到报告尺寸仍可读|
|配色|低饱和、对比明确、色盲友好；统一读取 Scripts/config/colors\.yaml|
|质感|面向高分 SCI 发表：配色、字体、线宽、留白和排版需有高级感，达到期刊级 figure 水准；禁止软件默认主题直出，输出前按期刊 figure 标准逐项打磨|
|克制|避免彩虹色和无意义文字|
|可复现来源|所有正式分析图必须由 `Scripts/` 中可复现的 R/Python 等代码直接从结果证据链中的当前定稿分析数据集生成，并由脚本导出 PDF/PNG；不得使用生成式图片或 AI 图像工具、手工拼图、截图或图像编辑软件合成正式分析图|
|覆盖|适用且可解释的图形类型尽量全交；至少覆盖总览、分组、细节和比较视角|
|选图|每个结果叶子有 `Tables/figure\_index\.tsv`，索引不含 recommend/recommended 列；可在源 Results 的叶子目录按需提供 `figure\_gallery\.html`，不设置图片数量门槛，gallery 不进入交付压缩包|
|源数据|不附 source\.tsv；作图数据留存于 Data/Processed|
|命名|文件名直接体现分析对象、比较与图形类型；不得使用 Figure1、Fig1、panel\_A 或仅靠数字编号表达内容|
|拆分|单图只表达一个主要问题；能独立阅读的子图分别导出，不制作多面板拼图或 facet|
|基因表达|多个基因按基因逐张输出，每个基因分别交付同名 PDF 与 PNG，不把多个基因做成分面图|
|表达量统计|凡表达量图包含组间、条件间或时间点间比较，图内同时显示显著性星号和精确 P 值数字；优先使用 R rstatix 按实验设计计算、ggpubr 添加；以 donor/sample 等生物学重复为统计单位，配对设计使用配对检验，多重比较使用校正后 P 值；保留 `*.stat.full.tsv`，包含基因/指标、比较组、各组样本量、统计单位、检验方法、配对状态、原始与校正 P 值、校正方法、显著性标签及作图位置，并由 figure_index 关联；无可检验比较时在 stat 表记录 not_applicable 或 insufficient_n|
|箱线图统计|有足够样本且比较成立时，图内显示 ns/\*/\*\*/\*\*\*/\*\*\*\*；默认阈值为 ns ≥ 0.05、\* < 0.05、\*\* < 0.01、\*\*\* < 0.001、\*\*\*\* < 0.0001；多重比较优先使用校正后 P 值，并在结果表或 README 记录检验方法、精确 P 值、校正方法和统计单位；无法检验时明确标注 not tested 或 insufficient n|
|ROC|二分类结局继续使用 R `pROC`，生存结局继续使用 R `timeROC`；所有正式展示曲线必须平滑。每条候选曲线均先生成可核对统计表，至少记录模型/指标、队列、终点或时间点、样本量/事件数、AUC、置信区间及方法、阈值、敏感度、特异度和训练/验证角色。训练、内部验证和外部验证分别使用各自的无数据泄漏评估 AUC 独立判定：仅当对应 AUC ≥ 0.70 时，ROC 图及其统计表才可进入 Results；AUC < 0.70 的 ROC 图不交付，对应统计结果和内部图仅保留在 `Data/Processed/` 归档并记录排除原因，不得用训练 AUC 替代任一验证 AUC。不同终点、队列或时间点分别输出语义命名单图，不使用 facet；平滑仅用于展示，不使用平滑后的展示曲线重新计算 AUC、置信区间、阈值、敏感度或特异度|


## 5\.3 图形覆盖：适用类型尽量全交

核心｜工程师不得只交自己最习惯的一种图。只要方法适用、数据支撑且能够被正确解释，同一分析应同时覆盖总览、分组、细节和比较等互补视角；README 按图形类型说明用途，所有正式图通过语义和来源导航，不设置推荐状态。

- 全面不等于重复：仅颜色、尺寸、排序或坐标轴方向不同的重复图不算新的图形类型；确有阅读价值的横纵版、标签版和分组版可以保留。

- 同一类图跨组比较时必须统一色标、坐标范围、排序和图例；需要单独缩放时在 README 明确说明，避免视觉误导。

- 图形使用稳定的内容语义名，如 `GBM_vs_control_DEG_volcano`、`myeloid_SPI1_expression_GBM_vs_control_boxplot`；同一内容的 PDF 与 PNG 共用基础名。

- 集合交集规则｜涉及集合交集/共有元素比较（多基因集、多 cluster marker、多队列 DEG 等）时，必须提供 Venn 图（≤4 个集合）或 UpSet 图（>4 个集合），并附交集计数表；仅展示独有元素不足以说明重叠关系。

## 5\.4 大图量交付：客户能快速浏览和挑选

每个结果叶子必须在 `Tables/figure\_index\.tsv` 提供图形索引；索引只记录图形 ID、PDF/PNG 相对路径、说明和来源表，不设置 `recommend` 或 `recommended` 列。可在叶子目录按需提供可离线打开的 `figure\_gallery\.html` 缩略图图库，不设置图片数量门槛；gallery 属于源 Results 的浏览辅助文件，交付压缩包必须排除所有 gallery 路径。

- 同一图形的 PDF 与 PNG 使用相同基础名；索引中的链接使用相对路径，保证解压后可直接打开。

- 多组、多细胞类型或多通路分析必须同时提供总体图、分组图和差异比较图。

**空结果规则｜****分析正常完成但没有显著结果时，可以保留空表，优先保留表头和稳定列；不得生成或保留占位图。绘图失败的信息只记录在 Processed 的运行摘要或日志中，不进入 Results。**

## HTML 展示内容

HTML 展示：交付 HTML 的正文、标题、导航、图注、文件卡片、表格预览、提示文字及辅助阅读文本均按分析内容描述，不出现软件包或绘图库名字（如 ytbiokit），也不展示内部文件子目录名、目录树或路径。例如以“基因表达与评分”代替“ytbiokit”，以“下载差异表达结果表”代替“21.ytbiokit_scrna/Tables/DEGs.full.tsv”。链接及图片加载所需的真实相对路径可保留在 href/src 等资源属性中，页面上的链接文字使用结果名称，不把路径输出为可见文字、title、alt 或 aria-label。软件包名、版本和实现细节仅写入内部运行记录；分析方法使用相应的分析名称描述。若其他报告规范要求直接展示包名或完整文件子目录，以本条 HTML 展示规则为准。交付前检查页面、导航、图注、文件卡片、预览及提示文字，并验证相对链接有效。

## 参考色系

每个项目在 Scripts/config/colors\.yaml 单独配置颜色。推荐将高亮色限制在 1–2 个；灰色承载背景和非重点信息。图形以高分 SCI 期刊发表为目标，配色和整体视觉需有高级感：低饱和主色、明确视觉层级、充分留白、统一字体与线宽。
